# 深渊放置姬 · Mod 修改内容说明

## 当前包含的 Mod

### 深渊调试台（IdleAbyssMod）v1.0.0

游戏内按 **F1** 打开 / 关闭的调试面板，像素风界面与游戏本体一致，支持 `－/＋` 调整整个面板
（含文字）的缩放，标题栏可拖动。所有改动**即时写入存档**。
适配游戏 **3.0.0**。

**v1.0.0 起是官方模组包**（3.0.0 新增的模组系统）：不再修改 `resources/app.asar`，
模组本体就是一个文件夹，放进 `%APPDATA%\IdleAbyssPrincesses\mods\chenxi_abyss_debug\`
就生效；游戏更新不会再把 Mod 冲掉，也不用 Python。面板入口有三处：
F1、顶栏「调试」按钮、设置 → 模组 → 深渊调试台。

**资源页**

- 金币、魂晶（账号共用）、余烬之魂、秘境钥匙（上限 50）、钥匙碎片（满 10 换 1 把钥匙，最多 9）、
  扭蛋券、强化祝福、王庭锭、王庭碎片（普通 / 英雄 / 神话三档）、
  **最后的余烬**（超高难本货币，终焉升华用，账号共用）、
  **深渊结晶**（`A.raid.crystal`，秘境 46 层以上通关、铁匠灌注、重复神话折给的那个，账号共用）、
  **蚀心 / 守心符 / 深渊之泪**（2.8.3 深渊誓约的三种货币，在角色档 `S.abyss`，**角色绑定**，
  换角色不通用；蚀心用于铁匠「蚀刻」，守心符要誓重 ≥ 40、深渊之泪要誓重 ≥ 80 且评级 ≥ 400 才掉）
- 宝石库存：6 种宝石 × 5 个品级，逐格可改
- 每行支持「设为」「＋」（在当前值上加输入框里的数）「清零」，输入框支持 `1.5万` / `2亿` / `3k` 简写
- **秘境高层**（只读区块）：历史最高层、本周秘境碎片（三档难度各 x/6，满了游戏自动降到下一档）。
  故意不给改 —— 碎片计数每档每周最多 6 个、换周会被 `riftDeepWeek()` 清零，改小了等于凭空多刷一遍

**装备页**

- 列出已装备 / 背包 / 个人仓库 / 共用仓库的全部装备，可按来源筛选、按名称搜索。
  点选装备时只重画右侧编辑器，左侧列表的滚动位置不会跳回顶部
- 改品质（普通~套装）、上古、太古（太古会自动把所有词缀拉到满值）
- 改物品等级（新规则上限 100）、强化等级（0~15）
- 改基础数值：武器最小/最大伤害、护甲、副手加成、格挡，全部夹在游戏自己的掷点区间内
- 词缀：可增、删、改词条与数值。数值上限 = 该装备当前等级与品质下能掷出的最高值，
  超出会被自动夹住；词缀条数受品质与等级限制（与掉落规则一致）
- **「词缀全满」按钮**：一键把每一条可改词缀顶到区间上限，普通装备与王庭装备都有
  （王庭没有太古变体，靠这个按钮满值；王庭那条生命词条也会一起顶满）
- 镶嵌：给已有孔换宝石与品级，可在部位允许的上限内开孔
- **生成新装备**：顶部四个来源按钮，都调游戏自己的生成器，产出与正常掉落同规格，
  生成后进背包（或共用仓库）并自动选中
  - **主线**：`rollItem(ilvl, 品质, 部位, 本职业)`，物品等级上限 100
  - **王庭**：`raidRollItem(id, 难度, rng, { radiant })`。下拉框按职业分组
    （本职业排第一，然后是其余 7 个职业），最后是 4 件通用首饰与 2 件稀世；
    难度选普通 / 英雄 / 史诗，另有「辉耀 ×1.3」开关。三档都是 ilvl 100，
    品阶倍率随难度走；◆ 固定词条、王庭生命词条都由游戏自己掷
    - 本职业与通用首饰进背包，别职业的进共用仓库（与游戏自己的分流一致）
    - 稀世（永夜之心 / 女王的婚戒）也能直接生成
  - **奇物**：`rollOddity(键, 等级)`，20 件全可选，下拉框里标出「已拥有」的
    （奇物账号唯一，每件同时只存在一份）；生成时会写 `A.odd` 登记，
    本局游戏不会再掉一件重复的
  - **神话**：`mythRollItem(键, 本职业)`，51 只神兽按五个界分组，已拥有的标「已拥有」。
    底子就是「史诗辉耀王庭」的 `raidRollItem` 再剥掉王庭身份换成 `r = 7`（`myth.js:39`），
    所以词缀 / 基础值 / 固定生命全按辉耀倍率掷。**2.4.1 起生成的神话直接进账号的
    「神话仓库」（`A.myth.vault`）**，和游戏自己的掉落走同一条路（`items.js handleNew`
    里 `r = 7` 的分支就是 `mythVaultAdd`）；同时写 `A.myth.own[键]` 登记账号唯一性
    （不写的话游戏以为没拥有过，下次掉落会再给一件同款）。仓库里已有同款时拒绝生成
  - 分流规则照 `handleNew`，但**跳过自动装备与自动分解**，不会把身上的装备换掉
- **神话仓库（2.4.1）**：装备页多了「神话仓库」这个来源，可以像背包一样选中改词缀。
  神话存在账号档里，改动由 `NS.apply` → 游戏 `save()`（先写账号档再写角色档）一起落盘
- **神话装备（r=7）的编辑限制**：品质与基础值不开放手改（底子已按史诗辉耀掷好，
  改品质或翻辉耀都会和 `mythSeed` 对不上）；词缀可以改，区间按辉耀（×1.3）算。
  这一条靠 `NS.radFlag(it)`（`radiant || myth`）统一判定 —— 神话的 `it.raid` 被删、
  `it.radiant` 被清成 `false`，如果只判 `it.raid` 就会退回主线低区间，一编辑就把数值压到 1/1.3
- **神话的白字和职业无关（2.4.1）**：主属性写成「主属性」（`AFF.main`，`mythOnly`），
  单一元素写成「全元素」，所以词条下拉走游戏自己的 `mythAffPool`（`myth.js:75`）——
  里面没有力量 / 敏捷 / 智力，也没有具体元素。手写这些词条的话，读档时
  `mythNeutralAff` 会改回去，不如一开始就不给选
- **王庭装备的品阶与「辉耀」**：王庭装 `r = 6`，在掉落体系里就是主线的**传奇（r=3）/ 套装（r=4）**
  那一档，用 `kind` 区分——`set` 是套装件（如「猩红誓约」），`leg` 是带王庭特效的传奇件
  （如武器「处刑」）。王庭没有上古 / 太古（`raidItemFix` 里硬写 `anc = false`），
  取而代之的是**辉耀（radiant）**，等价于主线的上古：
  - 面板上是一个「辉耀（数值 ×1.3）」开关，可自由开 / 关
  - 切换时四类数值一起变：基础值 ×1.3、随机词缀按掷点位置重算（上限 ×1.3，硬上限 ×1.25）、
    生命词条 ×1.3、◆ 特效词条按 `RAID_EFFECTS` 表重建（`raidItemFix`）
  - 来回切能完全还原（实测基础值与词缀差值为 0）
  - 装备副标题会写成「武器 · 王庭 · 传奇（处刑） · 辉耀 · ilvl 100」这种形式
- 王庭装备的品质按钮与基础数值仍然不开放手改（由品阶倍率决定）
- 王庭词缀区里两种「特殊行」的区别：
  - **◆ 开头的才是固定词条**（如 ◆ 暴击几率、◆ 技能伤害），值由 `RAID_EFFECTS` 表定义，
    读档时 `raidItemFix` 会整条重建，手改存不下来，所以只读
  - **生命词条不是固定词条**：它是王庭防具必带的一条普通词缀（装备卡上也没有 ◆），
    只是数值按王庭专用的 `RAID_LIFE_MUL` 公式掷、不适用主线 `life` 的区间。
    它和别的词缀一样有下拉框，可以换成任意合法词条，也可以删
  - 下拉框里有一个 **「生命·王庭」** 选项，选中就是把这条变成王庭生命词条
    （数值按 `RAID_LIFE_MUL` 算，比普通 life 大一个量级）。一件装备只能有一条，
    已有的时候其他行不会出现这个选项
  - 只有带 `RAID_LIFE_MUL` 的部位（护甲类、首饰）才有这个选项，武器 / 副手没有
- 奇物（r=5）只开放强化等级，避免破坏奇物表的语义
- **灵器（r=8，DLC《炼妖壶》）**：白装底子封进器灵，词条全部来自器灵
  （`yaoItemFix` 读档时整条重建），所以只开放**强化等级**与**宝石**；
  词缀和基础值以只读列表展示，避免改了存不下来。器灵沉睡（没买 DLC / 文件没下载）时
  页面上会明确提示「只剩白装底子」
- **深渊蚀刻（2.8.3）**：装备副标题与列表会标出「深渊阶 n（×倍率）」「腐化」「铭文」「角色绑定」。
  深渊阶乘在强化后面（`plusM = (1+.08×plus) × abyssItemMul`），所以词缀区间不变，
  「强化后」的显示值会自动带上这一层
  - **腐化**（`it.abyss.cor = 1`）的装备在游戏里已经不能强化 / 附魔 / 打孔 / 升华 / 灌注 / 蚀刻，
    只能换宝石；调试台仍然允许改词缀和等级，但页面上会写明「属于绕过限制」
  - **角色绑定**（`it.bind = 1`）的装备不会放进共用仓库 —— 生成器分流时会避开，
    只走背包 / 个人仓库（游戏本身也拦着这类操作）
- **灵器的孔数**用游戏的 `mythSockMax` 判定：灵器默认不能打孔（精卫之魂例外 1 孔），
  神话精卫多 1 孔；腐化词缀「多孔」超出的孔位也会保留，不会被面板裁掉
- **深渊蚀刻区块（v0.9.1，在编辑器最下面）**：选中一件可蚀刻的装备就出现，
  针对**这一件**操作，不用另做装备选择器。可蚀刻 = 传奇 / 套装 / 王庭 / 神话 / 灵器
  （`ABYSS_ETCH.rars`），奇物与印记不行
  - 顶部一行状态：深渊阶 `n/5`、已用次数 `n/6`、是否腐化、当前铭文
  - **蚀刻一次**：直接走游戏的 `abyssEtch`，扣蚀心、掷成功率、失败时走游戏的失败表。
    条件不满足时会说清原因（蚀心不够 / 次数用完 / 待选铭文没选 / 已满阶 / 已腐化）
  - **回满次数**：把已用次数清零（`n = 0`），不动阶数与腐化状态。
    本来就没用过的装备会提示「次数本来就是满的」
  - **立即腐化（双重）**：跳过蚀刻，直接做一次双重腐化，不消耗蚀心 / 深渊之泪、不占次数。
    走游戏的 `abyssCorrupt`，所以**绑定、加孔、阶数变化**的规则与正常腐化完全一致
  - **取消腐化**：`cor = 0` 并清掉腐化词缀，之后又能强化 / 附魔 / 打孔 / 升华 / 灌注 / 蚀刻。
    游戏源码里注释提到 `it.abyss.pre`（腐化前的阶数与次数），但 `abyssCanon` 从来**不写**
    这个字段，所以无法回滚腐化时掉掉的阶数——**当前阶数保留**，需要的话自己再蚀刻回来。
    腐化词缀「多孔」加出来的孔**保留**，避免孔里的宝石丢失
  - **5 阶铭文**：下拉框列出本部位的全部铭文（`ABYSS_INSC` 按 `sockCat(it.t)` 过滤）。
    - 选了之后，蚀刻到 5 阶时游戏本来会随机给 3 条待选，Mod 把**自选那条换到第一位**
      （另外两条保留，还是可以在游戏里改主意）
    - 「直接装上」按钮：满阶且未腐化时直接写成 `insc`，不用去游戏里点三选一
  - **腐化词缀**：两个下拉框（最多 2 条）。选了就按这个顺序取，只选 1 条时另一条随机补；
    留空 = 原版随机。选「多孔」时加孔的副作用照常生效
  - 三个**全局开关**（记在 `localStorage`，换装备 / 重启游戏都保留）：
    - **蚀刻必定成功**：点「蚀刻」的那一瞬间把该阶成功率临时改成 100%，调用完立刻还原。
      不改游戏的表，所以深渊之泪、回归基线读到的还是原值
    - **蚀刻不消耗次数**：蚀刻后把 `it.abyss.n` 还原成调用前的值，次数用完也能继续升阶，
      每件仍然最多 5 阶
    - **腐化必定双重**：把腐化结果表换成只有 `twin` 一项，原函数自己的「2 条词缀 / 加孔 /
      阶数变化」全照走。同时管住两条腐化路径：**蚀刻失败**与**深渊之泪**
  - 全部靠包装游戏的三个顶层函数实现（`abyssEtch` / `abyssCorrupt` / `abyssRollCaff`），
    开关关掉时原样转发，行为和未装 Mod 一致。启动后日志里有一行
    `[IAP] 蚀刻钩子 111 全部挂上`，三位分别对应这三个包装
- **骊龙宝珠「探骊」区块（v0.9.2，在蚀刻区块下面）**：骊龙宝珠是「改写」类神格，
  装上之后铁匠「附魔」页签会对每件装备多出一个「探骊」按钮 ——
  每次花 `MYTH_PEARL.gold`（1 兆）金币，按 `MYTH_PEARL.rate`（1%）× 神契倍率
  （每级 ×1.1）多出一条随机词条，每件最多一次（`it.pearl = 1`），失败只花金币
  - 只在**这件能探骊**时出现（`mythPearlFits`：非神话 / 非灵器 / 非奇物 / 非印记 /
    未锁定 / 未探骊过 / 有词缀 / 未腐化）。已经探骊过的只留一行状态
  - 没拥有骊龙宝珠时整块不显示；拥有但**没装备**时提示「先把骊龙宝珠戴上」，按钮禁用
    （游戏里几率为 0，这里是硬门槛，没有绕过）
  - **探骊必定成功**（开关）：调用期间把 `MYTH_PEARL.rate` 临时放大到「p ≥ 2」，
    `finally` 里还原。不改 `mythPearlRate` 本身（它是 `const` 箭头函数，覆盖不了）
  - **指定词条**（下拉）：留空 = 游戏随机；选了就在成功之后把刚 push 进去的那一条
    换成自选的（走游戏的 `rollAff`，词条区间 / 太古满值规则照旧）。
    下拉只列**这件合法**的词条池（`affRollPool` 去掉已有词条与 `ele`），
    所以不会造出游戏不允许的组合
  - **探骊一次**（按钮）：直接调游戏的 `mythPearl`，扣金币、写 `it.pearl`、
    打游戏自己的 log 与横幅，成功与否都即时存盘
  - **已经探骊过的装备也能改**（v0.9.4）：区块会显示「已多出一条：X」，下面有
    「换成」下拉 + **换掉**（把探骊加的那一条换成指定的，不花金币），
    以及 **撤销探骊**（删掉这条并清 `it.pearl`，之后可以重新探骊）。
    早先版本这里只写一行「已多出一条词条」，把操作全藏起来了，看起来像装备坏了
  - 哪一条是探骊加的：王庭装备读档时 `raidItemFix` 会把 ◆ 固定词条全部删掉再追加到末尾
    （`raid_items.js:418`），所以**最后一条非 `raid` 词缀**就是它；主线装备没有 raid 词缀，
    最后一条就是它
  - 开关与指定词条记在 `localStorage`（`myPearlOk` / `myPearlAff`）；
    「换掉」下拉的选择只在内存里，不跨装备沿用

**进度页**

- 等级（1~70）、巅峰等级（新规则封顶 3000）、最高阶段（新规则封顶 101 / 旧规则无上限）、
  当前阶段、已解锁折磨档位、当前折磨档位、未分配属性点

**团本页（永夜王庭）**

- **必定掉落**（开关）：单人挑战每个首领保底掉 1 件王庭装备。
  游戏原本单人基础掉落 0 件、只有 20% 几率掉 1 件
  （`RAID_BAL.drops = { base: { 1: 0, ... }, extra: { 1: .2, ... } }`）。
  补出来的那件同样会参与女王的稀世判定（见下），所以开这个开关后
  女王的稀世概率从 20% × 1% = 0.2% 提到约 1%
- **只掉本职业 / 通用**（开关）：单人掉落池只留本职业装备与全职业通用首饰。
  游戏原版掉落池不按职业过滤（`raidLootTable` 只按首领筛），8 个职业混在一起，
  单人打本职业只占 1/8，掉到别职业的只能进账号共用仓库。
  开启后把掉落里别职业的装备换成同部位、本职业的版本（重新走 `raidRollItem` 生成，
  武器名 / 基础值 / 词缀池都跟着换），通用首饰与稀世原样保留。
  女王的首领池只有武器，过滤后只剩 1 件，所以掉的一定是本职业武器
- **无限掉落资格**（开关）：单人掉到装备也不消耗本周该首领的资格，可以一直刷
- **女王稀世概率**（数值）：直接改写 `RAID_BAL.relic`（原版 0.01），
  游戏自己的判定逻辑不用改就按新概率走。输入框可填任意百分比，
  另有 1% / 10% / 50% / 100% 四个快捷档；设为 100% 就是每次通关必掉永夜之心或女王的婚戒
- 以上三个开关 + 稀世概率都**只对单人挑战生效**，联机团本的掉落与资格完全走游戏原逻辑

## 安装 / 卸载

```bash
# 构建 + 安装（首次会自动备份原始 app.asar 为 resources/app.asar.orig）
python scripts/mod_build.py --install

# 还原成原版
python scripts/mod_build.py --restore
```

Steam 校验游戏文件或游戏更新后 `app.asar` 会被覆盖，Mod 消失，重新执行 `--install` 即可。

### 打包分享

```bash
python scripts/mod_pack.py            # 生成 dist/深渊调试台-v<版本>-分享包.zip
python scripts/mod_pack.py --asar     # 额外塞入 build/app.asar（约 100MB，不推荐）
```

分享包**不含游戏文件**，内容是 Mod 源码 + `mod_build.py` + `安装.bat` / `还原.bat` /
`安装说明.txt`。对方解压到自己游戏根目录、双击 `安装.bat`，用**他自己的** `app.asar`
现场注入，所以不挑游戏版本，也不会二次分发游戏资源。包内只有纯文本安装说明，
本文件（功能台账）不进包。

### 2026-11-02（v0.9.3）修放大后面板底部看不到 / 滚不到底

用户反馈：「资源、装备、秘境这些页需要加个滚轮，不然放大之后看不到下面的内容了」
「深渊页有滚轮但是滚到最下面没有显示完全」。

根因不是「没加滚动」，而是面板用 `transform: scale()` 缩放 —— **布局尺寸不变，视觉尺寸 ×scale**，
四处叠加：

1. `#iap-panel` 的 `max-height: calc(100vh - 24px)` 是**布局像素**。放大到 186% 时
   面板可视高度变成 1.86 倍，底部连同 `.iap-body` 的下边缘和滚动条一起跑到屏幕外。
   → `mod_panel.js` 新增 `fitBox()`，按 `1/scale` 折算成布局像素再写 `max-height`
   （宽度同理收一下，免得小窗口放大后右边也出去）
2. 内容没超出布局高度时 `.iap-body` 本来就不需要滚（资源页就是这样），
   于是「没有滚轮」和「看不到下面」同时出现。修完第 1 条之后，需要滚的时候滚动条自然出现
3. `.iap-hd` / `.iap-tabs` / `.iap-ft` 是 flex 列里的项，默认 `flex-shrink: 1`，
   内容超高时会被一起压扁，页脚文字被切掉一半 → 三个都加 `flex: 0 0 auto`，
   只让 `.iap-body` 收缩（它本来就有 `min-height: 0`）
4. `applyPos()` 原来只保证 40px 留在屏幕内，面板可以整体往下挪出屏幕；现在面板高度≈窗口高度，
   再偏一点底部就出界 → 改成整块夹在可视区（`0 ~ vw-w-8` / `0 ~ vh-h-8`），
   并在 `renderBody()` 之后重夹一次（从矮页切到高页时面板会长高）

另外给 `.iap-body` / `.iap-eqitems` 加了 `overscroll-behavior: contain`，
滚到底不再把滚轮漏给游戏页面。

验证：自检直接量 `getBoundingClientRect()`（受 transform 影响，是真实视觉尺寸）——
190% 下 `panel=1216, pbot=1224`（视口 1240），八个页签滚到底后最后一个元素都在可视区内
（`last=.../ok`）；截图确认资源页能滚到宝石库存表、深渊页最后一条誓约「血契」完整显示、
页脚「立即存档」四条边都在。
